# Реєстр «написано, але не перевірено наживо»
Оновлюється кожен блок. Знімається після Блоку 0 (Vercel-імпорт) і прогону.

## Блок 1 — дашборд пари
- [ ] Вкладка «Відповіді»: зведення, розбивка меню, CSV (кирилиця/BOM в Excel)
- [ ] Захист паролем: збереження в Share, гейт на /w/[slug], cookie 60 днів, усі 7 мов
- [ ] Локальний QR: генерація, завантаження PNG
- [ ] Вибір шаблону в дашборді після фіксу weddings.template_id
- [ ] Міграція: guest_password, rsvp_status, guest_group, invitation_sent (застосована в БД, не прогнана через UI)

## Блок 2 — Save the Date
- [ ] /std/[slug]: рендер до публікації, тема успадковується з шаблону
- [ ] Google Calendar лінк і .ics (Apple/Outlook) — відкриття на iOS/Android
- [ ] OG-картинка (edge runtime + service key на edge!) — прев'ю у Telegram/Viber
- [ ] Кнопка «Перейти на сайт» після публікації
- [ ] Блок STD у вкладці «Поділитися»

## Відомі ризики схеми
- Повний цикл (реєстрація → створення → оплата → публікація) жодного разу не запускався проти відновленої схеми.
